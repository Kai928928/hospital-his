# HIS Pro · 医院智能信息系统

基于 Flask + SQLAlchemy 的轻量级医院信息系统（Hospital Information System），覆盖门诊挂号、电子病历、处方开立、收费结算等核心业务闭环，内置运营总览仪表盘，适合作为医院业务建模、教学演示或二次开发的基础脚手架。

## 功能特性

- **运营总览**：今日挂号数、待就诊队列、科室负载、未结账单金额、就诊完成率等核心指标可视化
- **患者档案**：建档、检索、就诊历史聚合视图
- **医生资料**：按科室分类管理医生与职称
- **出诊排班与预约**：管理员按日期、上午/下午设置号源和挂号费，挂号员按排班预约并获取号序；支持暂停号源、取消释放与防重复挂号
- **门诊挂号**：挂号自动生成待缴费账单，状态流转（待就诊 / 已完成 / 已取消）
- **电子病历**：主诉、诊断、治疗方案记录，保存即同步更新挂号状态
- **药品目录与处方**：管理员统一维护编码、规格、单位、价格与启停；医生选药开方，保存历史价格和规格，自动生成处方账单
- **收费结算**：区分挂号费 / 药品费，核对明细后登记现金、银行卡、微信或支付宝收款；记录实收、找零、唯一流水与缴费时间，支持整单退费、收退费凭条及按日期、患者、流水号查询收支
- **演示数据**：内置一键填充命令，秒级启动可用
- **岗位账号**：管理员、挂号员、医生、收费员登录，医生账号关联接诊医生；新增、启停账号、重置和修改密码
- **操作留痕**：记录业务操作人、时间和对象，收款与退费凭条显示操作人员，管理员可筛选查询日志

## 技术栈

| 层级 | 选型 |
| --- | --- |
| 后端 | Flask 3.x |
| ORM | Flask-SQLAlchemy 3.x（SQLAlchemy 2.x） |
| 数据库 | SQLite（开箱即用，可平滑迁移至 MySQL / PostgreSQL） |
| 模板 | Jinja2 + Bootstrap 5.3 + Bootstrap Icons |
| 运行环境 | Python 3.10+ |

## 快速开始

### 1. 克隆仓库

```bash
git clone https://github.com/Kai928928/hospital-his.git
cd hospital-his
```

### 2. 创建虚拟环境并安装依赖

```bash
python -m venv venv
# Windows
venv\Scripts\activate
# macOS / Linux
source venv/bin/activate

pip install -r requirements.txt
```

### 3. 初始化数据库与演示数据

```bash
flask --app app init-db      # 创建表结构
flask --app app seed         # 填充科室 / 医生 / 患者演示数据
```

> 也可直接运行 `python seed.py`，一步完成建表与填充。

### 4. 启动服务

```bash
flask --app app run
# 或开发模式
python app.py
```

浏览器访问 [http://127.0.0.1:5000](http://127.0.0.1:5000) 即可进入系统。

仓库为私有仓库，下载需要对应的 GitHub 访问权限。仓库仅保存源码、文档和测试，不包含本机患者数据库、人员账号、登录密钥、日志、虚拟环境或测试缓存；演示数据由初始化命令生成，首次管理员由使用者自行创建。

### 首次登录与人员账号

未创建账号时，系统进入 `/setup`，由使用者设置首位管理员的姓名、账号和密码，无内置通用密码。之后由管理员在“人员账号”新增其他工作人员；医生账号必须关联已有医生资料，每位医生至多关联一个账号。

| 岗位 | 可用业务 |
| --- | --- |
| 管理员 | 所有业务、人员账号、操作日志 |
| 挂号员 | 患者建档、患者基本资料、医生资料、挂号及状态管理 |
| 医生 | 本人接诊患者、本人挂号、病历与处方 |
| 收费员 | 患者基本资料、账单、收款、退费、收支查询 |

各岗位登录后进入对应工作页面；菜单与按钮按权限显示，后端同时验证岗位和医生归属。挂号员、收费员不能通过患者详情查看病历摘要。账号停用、重置密码、本人修改密码后，旧登录失效；不能停用本人账号或最后一位管理员。

密码使用 Werkzeug 哈希保存。登录签名密钥默认随机生成并保存在 `instance/session-key`，也可通过 `HIS_SECRET_KEY` 提供；不要将此文件提交到仓库。登录有效期为 8 小时，所有写入表单校验会话令牌。升级后旧的匿名收费页面需重新登录并刷新。

关键业务和账号变更在同一数据库事务内保存操作日志；收款、退费凭条及收支流水显示操作人。历史账单不补造操作人。日志只保存操作摘要，不保存密码、病历正文或完整请求表单。

### 已有数据库升级收费功能

先备份 `instance/his.db`，停止旧服务，然后执行 `flask --app app init-db`，新增收款、退费流水、人员账号、操作日志、出诊排班与预约关联表后重新启动。此命令不重写历史挂号或账单；应用使用 Decimal 计算金额，新流水以整数分保存。现有 SQLite 金额列保持原物理类型，由 ORM 按两位小数读取；这不是数据库类型迁移。

收费从账单列表的“核对收款”进入，核对患者、费用及到账金额后提交。现金允许实收大于应收并记录找零，其他支付方式须金额一致。账单状态和唯一收款流水在同一事务保存，重复提交不新增收款。

历史合并账单仅在单次挂号只有一张账单，且总额恰等于药费加挂号费时展示完整项目；其他金额不一致的账单暂停收款。历史已缴账单不会补造流水。微信、支付宝与银行卡选项用于人工确认到账后的登记，尚未连接支付平台。

全额退费从已缴账单详情展开办理，金额固定为原收款净额（实收减找零），须填写原因并确认已原路退还款项。每条收款流水至多登记一次退费；保留原账单、收款金额和时间，退费后不能再次收款。未缴、零金额、金额不一致或缺少原收款流水的历史账单不能直接退费。目前未增加部分退费及支付平台退款调用。

“收支流水”按收款或退费各自的发生时间查询，结束日期包含当天全部时刻；可搜索患者姓名、电话、原收款流水或退费流水。合计只针对当前筛选范围。历史收款按原账单金额和原缴费时间展示，不补造流水号；未登记时间的历史收款仅出现在不限制日期的查询中。退费当日计支出，不回改原收款日的收入。

### 出诊排班与预约挂号

管理员在“出诊排班”新增医生出诊日期、时段、号源数和费用。时段为上午 08:00-12:00、下午 14:00-18:00；当日对应时段结束后不再接受新挂号。医生只查看本人排班，挂号员可查询所有排班并预约，收费员不管理号源。

新挂号必须选择有效排班，日期、医生和费用以服务端排班为准，不能自行改价。号源扣减、挂号、预约关联、账单及操作日志在同一事务保存。号源不足、暂停、过期、价格变化或同患者重复挂同一时段时拒绝办理。号序在同一排班内递增，取消后不复用；历史挂号显示为“历史挂号”，不补造排班和号序。

调整排班不能把号源总量降到已用人数以下；调价只影响后续新挂号，旧账单保持原价。暂停仅停止新增挂号，已有预约继续保留，不自动退费或通知患者。

只有未接诊挂号可以取消，正金额已收款须先办理退费。取消后释放号源、保留原预约和费用记录，未缴账单作废并从待收金额中剔除；零金额已结算挂号无需补造退款。已作废账单不能再收款，且取消和收款并发时只会有一个结果生效。

预约在就诊日期之前不能接诊；保存病历后才标记完成，不能由挂号窗口直接“完成”。运营总览的候诊队列只计当日，不将未来预约混入。医生接诊、取消和收费状态变更均在后端校验。

当前号源并发与同患者有效预约唯一性在 SQLite 上验证，后者使用部分唯一索引；切换数据库时需迁移该索引。

### 药品目录与选药开方

升级前备份数据库，停止服务并执行 `flask --app app init-db`，新增药品目录、处方药品快照和病历开方唯一关联表；不修改旧处方、账单或其物理表结构。

管理员先在“药品目录”录入编码、名称、规格、计价单位和单价，可检索、分页、调整资料或停用；编码不区分大小写且唯一。医生和收费员可查询目录，但不能修改。停用只影响后续开方，不删除历史记录。

医生开处方时选择目录药品，填写数量和用法用量；服务端按目录单价计算，不接受手工改名或改价。每张处方为 1 至 50 项，每种药品只出现一行，数量须为 1 至 99999 的整数。页面显示小计和合计，提交时再次检查在用状态与资料版本，药品已变更时要求重新核对。

处方保留开立当时的编码、名称、规格、单位和单价。后续调价、改名、停用不改变历史处方或应收金额。处方号可进入完整明细；收费凭条显示原规格和单位。历史处方未登记的规格明确标注，不推测补填。处方、药品快照、账单、唯一关联和日志同一事务保存，防止重复提交和并发重复计费。

目录默认不生成真实药品或推荐剂量，需由有权限的人员维护。目前不含库存、药房发药、处方审核或用药安全校验，不可代替临床药事系统。

## 数据模型

- **Department** 科室
- **Doctor** 医生（归属科室）
- **Patient** 患者
- **Registration** 挂号（患者 × 医生 × 日期，含状态与挂号费）
- **DoctorSchedule** 出诊排班（日期、时段、号源总量、已用数量、费用和号序计数）
- **ScheduleBooking** 预约关联（保留挂号与排班、号序、创建时间及是否占用号源）
- **MedicalRecord** 就诊记录（主诉 / 诊断 / 治疗方案，归属挂号）
- **Prescription** + **PrescriptionItem** 处方与药品明细
- **Bill** 账单（挂号费或处方费，含缴费状态与时间）
- **BillPayment** 收款流水（每张账单至多一条，记录支付方式、整数分金额、实收、找零及流水号）
- **BillRefund** 退费流水（每条收款至多一条，记录原收款、全额退款金额、原因、时间与退费流水号）
- **User** 工作人员账号（密码哈希、岗位、关联医生、启停状态、会话版本）
- **OperationLog** 操作日志（操作人快照、动作、对象和摘要）

## 业务流程

```
挂号登记 → 生成挂号费账单 → 医生接诊 → 写入电子病历 → 挂号置为已完成
        → 按需开立处方 → 自动生成处方账单 → 缴费结算
```

## 配置说明

默认配置位于 `app.py`：

```python
app.config["SQLALCHEMY_DATABASE_URI"] = "sqlite:///his.db"
```

生产部署建议：

- 使用 `HIS_SECRET_KEY` 提供随机长密钥，或妥善保存自动生成的 `instance/session-key`
- 切换 `SQLALCHEMY_DATABASE_URI` 至 MySQL / PostgreSQL
- 关闭 `debug` 模式，使用 `gunicorn` / `waitress` 等 WSGI 服务器

## 开发与扩展

- 新增模块：在 `app.py` 添加路由、`models.py` 添加模型、`templates/` 添加模板
- 切换数据库：仅修改 `SQLALCHEMY_DATABASE_URI`，SQLAlchemy 自动适配方言
- 认证与岗位权限位于 `auth.py`，新增业务路由时需明确配置岗位权限
